# Sounds & Fog — نظام آراء العملاء

نظام ويب متكامل لجمع وتحليل آراء عملاء مطعم وكافيه **Sounds & Fog** في الرياض:
صفحة استبيان عامة سريعة بالعربية (RTL) مع إنجليزية اختيارية، ولوحة تحكم آمنة
للتحليلات ومتابعة الشكاوى، مع استيراد البيانات القديمة من Excel وتصديرها.

> **بدون أي حزم خارجية.** النظام مبني على Node.js فقط (HTTP، SQLite المدمجة،
> قارئ/كاتب Excel، ومولّد QR — كلها مكتوبة داخل المشروع). لا يوجد `npm install`
> ولا خطوة بناء.

---

## التشغيل السريع

```bash
cd sounds-fog-feedback

npm run setup                       # ينشئ .env وقاعدة البيانات وحساب المدير
npm run import -- ../response.xlsx  # استيراد ردود Excel القديمة (295 ردًا)
npm run seed                        # بيانات تجريبية لعرض اللوحة (اختياري)
npm start                           # http://localhost:3000
```

| الصفحة | الرابط |
|---|---|
| استبيان العميل | `http://localhost:3000/` |
| النسخة الإنجليزية | `http://localhost:3000/?lang=en` |
| سياسة الخصوصية | `http://localhost:3000/privacy` |
| لوحة التحكم | `http://localhost:3000/admin` |
| فحص الحالة | `http://localhost:3000/healthz` |

بيانات الدخول الأولى من `.env` (`ADMIN_EMAIL` / `ADMIN_PASSWORD`)، ويُطلب تغيير
كلمة المرور إجباريًا عند أول دخول.

**المتطلب الوحيد:** Node.js 22.5 أو أحدث (يُنصح بـ 24).

## 1) صفحة العميل

- بلا تسجيل دخول، تُكمل في أقل من دقيقة، ومصمّمة للجوال أولًا.
- الجنس (اختياري) · المنطقة في الرياض (مطلوبة) · كيف سمع عنا (اختيار متعدد).
- تقييم بالنجوم لخمسة بنود: الموظفون، الشيشة، الطعام، المشروبات، سرعة الخدمة.
  **ترك أي بند فارغًا مسموح** ولا يدخل في حساب المتوسط.
- سؤالان مفتوحان، والاسم ورقم الجوال اختياريان، مع مربع موافقة على الخصوصية.
- رسائل تحقق عربية واضحة بجانب كل حقل، وتنقّل بالنجوم عبر لوحة المفاتيح.
- شاشة شكر أنيقة، بنص مختلف للتقييمات المنخفضة، مع زر مشاركة ونسخ الرابط.
- يعمل النموذج حتى لو تعطّل JavaScript (إرسال HTML تقليدي).

### منع الإرسال المكرر

ثلاث طبقات بلا أي إزعاج للعميل:

1. **بصمة جلسة** عشوائية في `localStorage` (لا تحتوي بيانات شخصية) — تمنع إعادة
   الإرسال خلال `SUBMISSION_COOLDOWN_MINUTES`.
2. **حد لكل IP**: `SUBMISSIONS_PER_IP_PER_HOUR` (يُخزَّن الـ IP مُعمّى فقط).
3. **كشف التكرار بالمحتوى**: رد مطابق من نفس الجهاز خلال 30 دقيقة.

في الحالتين 1 و3 يرى العميل شاشة الشكر العادية ولا يشعر بأي رفض.

|---|:--:|:--:|:--:|

| تعيين الردود لموظف | ✅ | ✅ | ❌ |
| **إظهار رقم الجوال كاملًا** | ✅ | ✅ | ❌ |
| تصدير Excel / CSV | ✅ | ✅ | ❌ |
| استيراد البيانات | ✅ | ❌ | ❌ |
| إدارة المستخدمين | ✅ | ❌ | ❌ |

مدير الفرع وموظف الخدمة يريان ردود فرعهم فقط.

### اللوحة الرئيسية

إجمالي الردود · متوسط التقييم العام · متوسط كل بند على حدة · نسبة التقييمات
المنخفضة (1–3) · عدّادات اليوم/الأسبوع/الشهر · مخطط زمني للردود والتقييمات
(تتغيّر دقته تلقائيًا بين يوم وأسبوع وشهر حسب طول الفترة) · مصادر معرفة العملاء ·
توزيع مناطق الرياض · توزيع النجوم · اتجاه الملاحظات · أكثر الكلمات تكرارًا في
الملاحظات الإيجابية والسلبية (قابلة للضغط للانتقال إلى الردود) · قائمة الآراء
التي تحتاج انتباهًا عاجلًا.

### شاشة الردود

جدول كامل مع التاريخ، الاسم، **الجوال مخفي جزئيًا** (`+9665••••4567`)، المنطقة،
مصدر الزيارة، التقييم العام، الاتجاه، وحالة المتابعة — مع بحث نصي وفلاتر
(التاريخ، المنطقة، المصدر، الحالة، الاتجاه، مستوى التقييم، "تحتاج متابعة")،
وترتيب بالضغط على العناوين، وترقيم صفحات.

بالضغط على أي صف تُفتح لوحة تفاصيل جانبية: كل التقييمات، نصوص العميل، إظهار رقم
الجوال للمخوّلين (مع تسجيل العملية)، تغيير الحالة
(جديد → قيد المراجعة → تم التواصل → تم الحل → مغلق)، تعيين مسؤول، وملاحظات
الفريق الداخلية.

### التحليلات

مقارنة الفترات (اليوم/الأسبوع/الشهر مقابل الفترة السابقة بنفس الطول، أو فترة
مخصصة) · أفضل وأسوأ الجوانب أداءً · التقييم حسب المصدر والمنطقة ·
**فرص التحسين المقترحة** مرتبة حسب عدد الشكاوى وشدة التقييم، مع أمثلة من كلام
العملاء.

> كل مخرجات التحليل الآلي (اتجاه المشاعر، المواضيع، أسباب المشكلات) **اقتراحية
> وتحتاج مراجعة بشرية** — وهذا مكتوب صراحة داخل الواجهة.

### كيف يعمل تحليل اللغة العربية

مبني على معجم عربي داخل `src/nlp.js` بلا أي خدمة خارجية:

- تطبيع الحروف (أ/إ/آ → ا، ى → ي، ة → ه) وإزالة التشكيل والتطويل.
- معجم إيجابي/سلبي بأوزان 1–3، مع معالجة **النفي** ("ما هو ممتاز" → سلبي)
  و**المؤكّدات** ("بطيء جدًا").
- صور صرفية: أداة التعريف وواو العطف كسوابق، وألف النصب كلاحقة
  ("باردًا" → "بارد").
- اتجاه الرد النهائي يمزج نص الإعجاب + نص التحسين + التقييم الرقمي بأوزان مختلفة.
- 12 موضوعًا مُعرَّفًا (سرعة الخدمة، الأسعار، الجمر، النظافة، التكييف، الزحام…)
  تُربط بالبنود منخفضة التقييم لاقتراح السبب.

بعد أي تعديل على المعجم، شغّل `npm run reanalyze` لإعادة احتساب الردود المخزّنة
(لا تُمَس البيانات الأصلية).

## 3) البيانات والخصوصية

- **SQLite** بمخطط منظّم ومفهرس (`src/db.js`): الردود، الملاحظات الداخلية،
  المستخدمون، الجلسات، دفعات الاستيراد، وسجل العمليات.
- الاسم ورقم الجوال اختياريان دائمًا.
- يُخزَّن الجوال بصيغتين: كما أدخله العميل، وصيغة موحّدة `+9665XXXXXXXX` للبحث.
- **الإخفاء الجزئي افتراضي في كل الواجهات**، حتى في شاشة التفاصيل؛ والإظهار
  الكامل يحتاج صلاحية `phone:reveal` ويُسجَّل في سجل العمليات باسم المستخدم.
- لا يُحفظ عنوان IP الخام — فقط تجزئة HMAC قصيرة.
- كلمات المرور بـ **scrypt** بملح عشوائي، وجلسات على الخادم مع كوكي
  `HttpOnly` + `SameSite`، وإيقاف مؤقت بعد 8 محاولات فاشلة.
- ترويسات أمان كاملة على كل استجابة (CSP, `X-Frame-Options`, `nosniff`…).
- صفحة سياسة خصوصية مختصرة بالعربية والإنجليزية.

### النسخ الاحتياطي

```bash
npm run backup     # نسخة فورية
```

نسخة تلقائية كل `AUTO_BACKUP_EVERY_HOURS` ساعة (افتراضيًا 24)، تُنتج ملف قاعدة
بيانات متسق عبر `VACUUM INTO` + تصدير CSV للبيانات الخام، ويُحتفظ بآخر
`BACKUP_KEEP` نسخة في `data/backups/`.

## 4) نقل البيانات الحالية

```bash
npm run import -- ../response.xlsx --dry-run   # معاينة بلا كتابة
npm run import -- ../response.xlsx             # تنفيذ
```

أو من لوحة التحكم: **استيراد البيانات** → اسحب الملف → راجع المعاينة → تأكيد.

يطابق النظام هذه الأعمدة تلقائيًا بالعربية أو الإنجليزية:
`Timestamp`، `Gender`، `Region`، `How did you hear about us`، `Staff Rating`،
`Shisha Rating`، `Food Rating`، `Drinks Rating`، `Service Speed`،
`What did you like`، `What made you dissatisfied`، `Name`، `Phone Number`.

**ما يفعله التنظيف** (دون تعديل أي خلية أصلية):

| الحالة | المعالجة |
|---|---|
| صف العناوين ليس الصف الأول | يُكتشف تلقائيًا بأعلى تطابق |
| عمود التاريخ بلا عنوان واضح | يُستنتج من شكل القيم (أرقام Excel التسلسلية) |
| تقييم خارج 1–5 (مثل `83`, `147`) | يُعتبر مفقودًا ولا يدخل في المتوسط |
| نص ملاحظة رقمي بحت (`38`, `44`) | يُعتبر فارغًا (أثر أعمدة مزاحة في الملف) |
| خانات فارغة | تبقى فارغة ولا تُحتسب |
| `أنثي-Famale` / `ذكر-Male` | تُطابق بأطول مرادف أولًا لتفادي الخطأ |
| مصادر متعددة في خلية واحدة | تُفصل إلى قائمة |
| رقم جوال غير صالح | يُحفظ كما ورد، بلا صيغة موحّدة، ويُدرج في تقرير الملاحظات |
| تواريخ Excel | تُفسَّر كتوقيت الرياض وتُحفظ UTC |

الصف الأصلي كاملًا يُحفظ في `raw_payload` ولا يُعدَّل أبدًا. كل صف له بصمة
فريدة، لذا **إعادة الاستيراد آمنة ولا تُنتج تكرارًا**.

نتيجة ملف `response.xlsx` الحالي: 295 ردًا، 29 تقييمًا غير صالح نُظّف،
257 نصًا رقميًا أُهمل، ورقم جوال واحد غير صالح.

### التصدير

من شاشة الردود: **تصدير Excel** (ملف `.xlsx` حقيقي بترويسة مجمّدة وفلاتر
وتنسيق RTL) أو **CSV** (بترميز UTF-8 مع BOM ليفتح في Excel العربي مباشرة).
يشمل التصدير كل النتائج المطابقة للفلاتر، ويحترم صلاحية إظهار الجوال.

## 5) رمز QR

من لوحة التحكم → **رمز QR**: معاينة فورية، وتنزيل PNG أو SVG، ونسخ الرابط،
وطباعة. أو من سطر الأوامر:

```bash
npm run qr                                  # يستخدم PUBLIC_BASE_URL
npm run qr -- https://feedback.example.sa   # رابط محدد
```

> قبل الطباعة للعملاء، اضبط `PUBLIC_BASE_URL` في `.env` على العنوان العام
> الحقيقي — وإلا سيقود الرمز إلى `localhost`.

## الإعدادات (`.env`)

| المتغير | الافتراضي | الوصف |
|---|---|---|
| `PORT` / `HOST` | `3000` / `0.0.0.0` | منفذ وعنوان الاستماع |
| `NODE_ENV` | `development` | `production` عند النشر |
| `PUBLIC_BASE_URL` | `http://localhost:3000` | العنوان العام (QR والمشاركة) |
| `DATABASE_PATH` | `./data/feedback.db` | مسار قاعدة البيانات |
| `SESSION_SECRET` | — | **غيّره قبل النشر** (32 بايت عشوائي) |
| `SESSION_TTL_HOURS` | `12` | مدة الجلسة |
| `COOKIE_SECURE` | `0` | اجعله `1` خلف HTTPS |
| `ADMIN_EMAIL` / `ADMIN_PASSWORD` | — | حساب المدير الأول |
| `SUBMISSION_COOLDOWN_MINUTES` | `10` | منع التكرار من نفس الجهاز |
| `SUBMISSIONS_PER_IP_PER_HOUR` | `12` | حد الإرسال لكل IP |
| `AUTO_BACKUP_EVERY_HOURS` | `24` | النسخ التلقائي (`0` = تعطيل) |
| `BACKUP_KEEP` | `14` | عدد النسخ المحفوظة |

## النشر

1. انسخ المشروع إلى الخادم وثبّت Node.js 22.5+.
2. `cp .env.example .env` ثم عدّل:
   - `NODE_ENV=production`
   - `PUBLIC_BASE_URL=https://your-domain.sa`
   - `COOKIE_SECURE=1`
   - `SESSION_SECRET=$(node -e "console.log(require('crypto').randomBytes(32).toString('hex'))")`
   - `ADMIN_PASSWORD` قوية
   - `DATABASE_PATH` على **قرص دائم** (مهم جدًا على المنصات السحابية).
3. `npm run setup` ثم `npm run import -- /path/to/response.xlsx`.
4. شغّل خلف عاكس (Nginx/Caddy) مع HTTPS، وفعّل إعادة التشغيل التلقائي
   (`systemd` أو `pm2`). النظام يقرأ `X-Forwarded-For` ويستجيب لـ `SIGTERM`.
5. راقب `GET /healthz`.

يناسب أي خادم يحتفظ بالملفات (VPS، Railway، Render، Fly.io). **لا يناسب**
المنصات عديمة الحالة (Vercel/Netlify Functions) لأن SQLite تحتاج قرصًا دائمًا —
وفي هذه الحالة استبدل `src/db.js` بـ PostgreSQL؛ فكل استعلامات المخطط معزولة في
هذا الملف.
